## Story

**Como** usuário de qualquer perfil, inclusive no celular,  
**quero** usar o sistema por uma interface web com mensagens claras e consultar a documentação da API,  
**para** fazer meu trabalho sem depender de ferramentas técnicas.

## Escopo

### Incluído

- Página única (HTML + Bootstrap 5 via WebJar + JavaScript sem framework) servida pela aplicação.
- Abas por perfil: recursos e reservas, minhas reservas, aprovações e uso, retiradas, administração (painel, cadastro, manutenção, relatórios, auditoria) e notificações.
- Erros da API mostrados com título, detalhe, campos e código de rastreio; todo texto da API é escapado (sem XSS).
- Compatível com a CSP `script-src 'self'` (sem script inline) e com o token CSRF.
- Contrato OpenAPI com título, descrição e esquema de autenticação (`/v3/api-docs`, `/swagger-ui.html`).

### Fora de escopo

- Calendário visual e edição de recursos pela interface (a API suporta).

## Critérios de aceite

### AC1 — Fluxo do Solicitante

**DADO** um Solicitante logado  
**QUANDO** pesquisar, verificar e reservar uma sala  
**ENTÃO** vê a confirmação; ao repetir, vê o conflito explicado; a reserva aparece em Minhas reservas.

### AC2 — Fluxo do Responsável

**DADO** uma solicitação pendente  
**QUANDO** o Responsável aprovar pela interface  
**ENTÃO** a reserva sai da fila e aparece como aprovada.

### AC3 — Mensagens compreensíveis

**DADO** credenciais inválidas  
**QUANDO** entrar  
**ENTÃO** vê "Usuário ou senha inválidos".

### AC4 — Responsivo

**DADO** tela de celular (390×844)  
**QUANDO** usar a interface  
**ENTÃO** não há rolagem horizontal e o menu respeita o perfil.

### AC5 — Segurança da página

**DADO** a CSP ativa  
**QUANDO** usar a interface  
**ENTÃO** não há erro de JavaScript nem violação de CSP.

### AC6 — Documentação

**DADO** um navegador  
**QUANDO** abrir /swagger-ui.html  
**ENTÃO** o contrato da API carrega.
